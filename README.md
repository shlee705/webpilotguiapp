# WebPilot Desktop 1.0.3

URL과 요구사항을 실제 WebTestPilot 백엔드에 전달하고, 백엔드가 현재 탐색 중인 페이지를 별도의 전용 Edge에서 보여주는 Windows GUI입니다. 화면에는 **웹사이트 버그 탐색중...**으로 표시합니다. 실제 검사·판정·보고서 생성은 백엔드가, Computer Use의 클릭·입력 표현은 앱에서 선택한 GPT 또는 Claude 모델이 담당합니다.

## 시작

1. `release/1.0.3/win-unpacked/WebPilot.exe`를 실행합니다. 배포 폴더 전체가 필요합니다.
2. 왼쪽 아래 **QA팀 → 실제 검사 백엔드**에서 GPT 또는 Claude, 계획·탐색 모델, 판정 모델과 백엔드 전용 키를 저장합니다. 예산·시간·페이지 수와 고급 검사 옵션의 기본값도 지정합니다. 이 값은 백엔드 폴더의 `.env`에 기록하며 새 테스트부터 적용됩니다.
3. **QA팀 → 화면 표현 AI**에서 별도로 **GPT (OpenAI)** 또는 **Claude (Anthropic)**를 선택하고, 그 아래의 **모델 → API 키**를 입력해 저장합니다. 기본값은 GPT-6 Luna이며 Claude의 초기 모델은 Claude Haiku 5.5입니다.
4. URL과 검사할 내용을 보내고 **테스트 설정 → 설정 바꾸기**에서 실제 백엔드의 제공자·모델·검사 요구사항·예산·탐색 시간·페이지 수를 입력합니다. 고급 설정에서 페이지 종류·턴·동시 실행 수·추론 수준·탐색 묶음 방식을 지정합니다. 화면 표현 모델은 별도 영역에서 설정하며, 동작 횟수 지정 없이 실제 백엔드 진행을 따라갑니다.
5. **시작하기**를 누르면 실제 검사가 시작됩니다. 백엔드가 탐색한 페이지를 전용 Edge에서 열어 관련 클릭·입력·스크롤을 보여줍니다.

시작 전에는 유료 모델 호출이나 사이트 검사를 하지 않습니다. 백엔드 실행 환경이나 선택한 서비스의 백엔드 전용 키가 없으면 구체적인 준비 오류를 표시합니다. 키 값은 채팅이나 로그에 입력하지 않습니다.

## 서로 분리된 모델과 API 키

| 설정 | 용도 |
|---|---|
| 화면 표현 AI 탭의 GPT·Claude 모델과 키 | 전용 Edge의 클릭·입력 표현. 메인 프로세스의 앱 설정에 암호화 저장 |
| 실제 검사 백엔드 탭의 제공자·계획 모델·판정 모델·키 | 실제 탐색·판정·보고서 생성. 백엔드 `.env`에 저장 |
| 백엔드 `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` | 선택한 제공자에 해당하는 키만 실제 검사 프로세스에 전달 |

화면 표현 AI의 모델이나 키를 변경해도 백엔드 설정은 바뀌지 않습니다. 백엔드 설정 변경도 화면 표현 AI에 영향을 주지 않습니다. 두 역할 사이에서 키를 복사하거나 대체하지 않습니다. 화면 표현 사용량은 서비스별로 따로 집계하고 백엔드 비용과 합치지 않습니다. 백엔드의 원본 기본 예산은 실행당 $10이며, 탐색의 새 대화 시작 제한은 40분입니다. 화면 표현은 실제 백엔드가 끝날 때 함께 종료합니다.

화면 표현 AI는 GPT와 Claude의 모델·키를 각각 저장하므로 서비스를 전환해도 이전 설정이 유지됩니다. 기존 버전의 GPT 설정도 유지합니다. 입력 중인 미저장 키는 서비스 전환 시 지워 다른 서비스로 전송하지 않습니다. 키는 메인 프로세스에서 Windows safeStorage로 암호화하며, 암호화를 사용할 수 없는 환경에서는 실행 중 메모리에만 둡니다. 설정 삭제는 현재 선택한 서비스에만 적용됩니다.

앱의 **연결 확인**은 선택한 서비스에서 해당 모델 정보를 조회하며 응답 생성은 하지 않습니다. GPT는 [OpenAI Responses](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses), Claude는 [Anthropic Messages](https://platform.claude.com/docs/en/api/messages/create)와 [구조화 출력](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)을 사용합니다. 모델 이름과 API 계약은 2026-11-26 공식 문서에서 확인했습니다.

- GPT: [키 발급](https://platform.openai.com/api-keys), [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)
- Claude: [키 발급](https://platform.claude.com/settings/keys), [모델 목록](https://platform.claude.com/docs/en/models/overview)

**화면 표현 AI 탭에 입력한 Anthropic·OpenAI 키는 화면 표현 전용**입니다. **실제 검사 백엔드 탭**에서 입력한 키만 백엔드 폴더의 `.env`에 저장합니다. 백엔드 키는 요청하신 방식대로 평문 `.env`에 저장하며 대화·모델 프롬프트·로그에는 보관하지 않습니다. 같은 이름의 환경변수 키가 있으면 그 키가 우선하며 설정 화면에 출처를 표시합니다. `.env`의 다른 설정·주석과 다른 제공자의 키는 유지합니다. 삭제도 선택한 제공자의 `.env` 키 항목에만 적용합니다.

백엔드는 계획·탐색 모델과 판정 모델을 각각 지정합니다. Claude 초기값은 Opus 5.5 / Sonnet 5.5, GPT 초기값은 GPT-6.2 Sol / GPT-6 Luna입니다. 실행 예산을 계산할 수 있는 모델은 GPT-6.2 Sol·Astra, GPT-6.1 Terra, GPT-6 Luna, GPT-5.4 mini 및 Claude Opus·Sonnet·Haiku 5.5입니다. 가격을 모르는 모델은 유료 호출 전에 중단합니다. GPT 실행은 [Responses 도구 호출](https://developers.openai.com/api/docs/guides/function-calling)과 이미지 입력을 실제 백엔드에 연결하며 기존 검사 도구와 결과 검증을 사용합니다.

백엔드 `.env`에는 `WEBPILOT_BACKEND_PROVIDER`, `WEBPILOT_BACKEND_OPENAI_PLAN_MODEL`, `WEBPILOT_BACKEND_OPENAI_TRIAGE_MODEL`, `WEBPILOT_BACKEND_ANTHROPIC_PLAN_MODEL`, `WEBPILOT_BACKEND_ANTHROPIC_TRIAGE_MODEL`과 각 제공자의 전용 키를 저장합니다. 실행 시작 시 선택값을 고정하고 그 실행의 결과·모델·제공자를 검증하므로, 나중에 설정을 바꿔도 이전 보고서를 다시 열 수 있습니다.

## 테스트별 백엔드 실행 설정

테스트 설정의 백엔드 값은 이번 실행에 적용하며 전역 키·모델 설정이나 화면 표현 설정을 바꾸지 않습니다. 새 계획은 QA팀에서 저장한 백엔드 제공자·계획 모델·판정 모델과 검사 기본값을 가져오며, 계획을 저장하거나 다시 실행해도 선택값을 유지합니다. API 키는 계획에 저장하지 않고 해당 제공자의 백엔드 전용 키를 실행 시 조회합니다.

QA팀의 **실제 검사 백엔드 → 새 테스트의 기본 검사 설정**에서 아래 기본값을 변경할 수 있습니다. 이미 만든 테스트나 실행 기록은 바뀌지 않으며 테스트별 변경은 전역 기본값에 저장되지 않습니다. 검사 기본값은 `.env`의 `WEBPILOT_BACKEND_BUDGET_USD`, `WEBPILOT_BACKEND_EXPLORE_MINUTES` 등 전용 항목에 저장합니다. 아래 표는 최초 설치 값입니다.

| 입력 | 실제 백엔드 인자 | 최초 기본값 |
|---|---|---|
| 대상 URL / 검사 요구사항 | `--url` / 실행별 `--requirements` 파일 | 입력한 값 |
| 백엔드 제공자 / 계획·판정 모델 | `--provider` / `--plan-model` / `--triage-model` | 백엔드 설정 |
| 검사 예산 / 탐색 시간 | `--budget` / `--explore-minutes` | $10 / 40분 |
| 방문 페이지 / 페이지 종류 | `--max-pages` / `--max-templates` | 30 / 8 |
| 종류별 탐색 턴 / 대화 최대 턴 | `--turns-per-template` / `--max-turns` | 25 / 40 |
| 종류별 검사 페이지 | `--pages-per-template` | 3 |
| 동시 탐색·판정 / 검사 실행 | `--concurrency` / `--workers` | 1 / 1 |
| 추론 수준 / 탐색 묶음 | `--plan-effort` / `--sessions` | medium / template |

허용된 항목만 네이티브에서 다시 검증해 실행합니다. 임의 명령줄, API 키, 추가 origin이나 쓰기 허용 플래그는 이 입력에 포함할 수 없습니다. 실행 보고서의 `run.parameters`에는 실제 적용한 값이 기록되며 GUI는 실행 요청과 일치하는지 확인한 후 첨부합니다. 기존 기록의 보고서는 당시 형식으로 계속 검증합니다.

탐색 턴은 페이지 수가 아니라 AI가 읽기·조작·계획 제출에 사용하는 대화 횟수입니다. 페이지 종류가 하나이면 **대화별 최대 턴**, 여러 개이면 **페이지 종류별 탐색 턴**을 사용합니다. 1~3턴처럼 짧게 설정하면 계획을 제출하기 전에 끝날 수 있습니다. 설정 화면의 **기본 턴 한도 적용**으로 각각 40턴·25턴을 선택할 수 있으며, 누르기 전에는 저장된 한도를 변경하지 않습니다. 계획을 만들지 못한 경우에도 실제 방문·점검 범위와 미검사 사유를 보고서에 남깁니다. 미검사 범위를 검사 완료로 바꾸거나 한도를 자동으로 늘리지는 않습니다.

대상 페이지를 하나도 열지 못하면 모델 호출 없이 실패 증거를 담은 미완료 보고서를 생성합니다. 연결 거부·시간 초과 등 사유를 구분하며 정상 검사 완료로 표시하지 않습니다. `127.0.0.1`/`localhost` 주소를 검사하려면 해당 포트의 웹 서버가 실행 중이어야 합니다.

## 백엔드 실행과 화면 표현

가져온 백엔드는 `feature/member-01/qa-v2` 브랜치의 `qa/` 제품 코드입니다. 출처와 원본 해시는 `webtestpilot-backend/LOCAL_SOURCE.json`, 가져온 시점의 비교는 `webtestpilot-backend/LOCAL_IMPORT.md`에 있습니다. GitHub에는 푸시하지 않습니다.

실제 흐름은 **사이트 구조 수집 → 탐색·계획 → Playwright 검사 → 판정·재현 → 보고서 생성**입니다. GUI는 실제 프로세스에서 받은 단계·현재 페이지 정보를 표시합니다. 전체 검사 진행률을 임의의 퍼센트로 추정하지 않습니다.

Computer Use는 백엔드와 다른 브라우저 세션입니다. 백엔드가 탐색 중인 같은 출처의 페이지로 화면을 맞추고, 선택한 서비스의 모델이 그 페이지의 URL·본문·조작 가능한 요소를 읽어 관련 동작을 선택합니다. 백엔드가 다른 페이지나 단계로 이동한 동안 만들어진 오래된 선택은 실행하지 않습니다. 이 화면 표현의 동작을 검사 증거나 버그 판정으로 사용하지 않습니다.

- 화면 표현에는 횟수 입력이나 고정 동작 상한이 없습니다. 백엔드의 새 탐색 관측에 맞춰 안전한 클릭·입력·스크롤을 선택합니다. 지정 계정의 로그인은 모델 선택과 별도로 처리하며 성공 동작 수는 활동 기록으로만 표시합니다.
- 새 백엔드 관측이 없으면 추가 모델 호출·조작 없이 기다립니다. **검사 계획 실행** 단계도 실제 검사 워커가 연 페이지와 수행 중인 동작에 맞춰 표시합니다. 위치 없이 단계만 갱신되거나 판정·보고서 단계인 경우에는 현재 화면과 실제 단계를 표시하며 기다립니다. 백엔드 완료·실패·취소 시 화면 표현도 종료합니다.
- 현재 페이지에서 안전한 동작을 찾지 못하면 제한적으로 다시 선택하거나 다음 백엔드 관측을 기다립니다. 이전 버전 기록에 저장된 횟수는 무시하며 재실행도 백엔드를 따라갑니다.
- 전용 Edge에는 검정 포인터의 이동·클릭만 표시합니다. 배너·전체 화면 테두리·포인터 이름표는 표시하지 않습니다.
- 포인터는 실제 마우스 이동을 따라가며 페이지 전환 뒤에도 위치를 유지합니다. 다음 백엔드 페이지로 연결되는 안전한 링크가 현재 화면에 있으면 그 링크를 가리킨 뒤 이동합니다. 클릭 효과는 실제 클릭에만 표시하고, 모션 감소 설정을 존중합니다.
- 신규 Computer Use 작업에서는 스크린샷을 수집·저장·전송하거나 셔터 효과를 사용하지 않습니다. 실제 백엔드는 판정에 필요한 증거를 자체 실행 폴더에 수집합니다.
- **Esc** 또는 **응답 중지**로 백엔드 프로세스와 전용 Edge를 함께 정리합니다. 앱 종료·화면 새로고침에서도 진행 중인 작업을 취소합니다.

Computer Use의 일시적 모델 오류는 제한적으로 재시도하며 이미 실행한 클릭·입력·로그인을 반복하지 않습니다. 화면 표현이 복구되지 않으면 그 사실을 알리고 실제 백엔드 검사는 계속 진행합니다.

## 로그인과 입력 범위

**로그인 계정 사용**에 지정한 계정과 로그인 URL은 이번 실제 백엔드 검사와 화면 표현용 Edge에 함께 적용합니다. 로그인 URL은 같은 출처로 제한하며 생략하면 대상 URL에서 시도합니다. 두 브라우저는 세션을 공유하지 않고 각각 로그인합니다. 화면 표현은 모델의 로그인 선택을 기다리지 않고 지정된 로그인 화면에서 네이티브 입력·클릭으로 한 번 로그인한 뒤 백엔드의 최신 관측 페이지를 따라갑니다. 실패하거나 전송 여부가 불명확하면 자동 재제출하지 않습니다.

프롬프트의 아이디·비밀번호 줄은 대화 기록에서 제거합니다. 계정값은 실행 중 메모리와 백엔드 자식 프로세스 환경에만 전달하며 `.env`, CLI 인자, 앱 설정 파일, 대화, 모델 요청, 로그에 저장하지 않습니다. 로그인 동기화를 위해 두 역할의 AI 모델·API 키를 공유하지 않습니다. 완료·취소 후에는 계정을 해제하며 다시 실행할 때 재입력합니다.

같은 출처의 명확한 HTML POST 로그인 폼과 일부 SPA 로그인 폼을 지원합니다. 사용자가 요청하고 계정을 지정했을 때만 제출하며, 로그인 제출과 성공을 구분합니다. 외부 SSO·추가 인증·CAPTCHA는 자동으로 처리하지 않습니다. 실제 백엔드의 로그인과 새 세션에서 상태 유지가 확인되어야 로그인 이후 기능을 검사한 것으로 기록합니다. 로그인 실패나 추가 인증이 필요한 경우는 미완료 범위로 표시합니다.

인증된 화면의 계정 정보는 모델 입력과 저장 증거에서 가립니다. 가린 값이나 화면 영역은 관측할 수 없는 부분으로 취급하며 성공·버그 판정의 근거로 사용하지 않습니다. 인증 상태도 실행 프로세스의 메모리로 전달하고 파일로 저장하지 않습니다.

화면 표현은 일반 검색창·제목·여러 줄 본문·편집기 입력을 지원하지만, 중복 등록을 막기 위해 게시·글 제출·서버 변경 요청은 차단합니다. 명시적으로 요청한 지정 계정 로그인만 별도 검증 절차로 허용합니다. 백엔드도 기본 쓰기 차단 정책을 유지합니다. 결제·삭제·계정 변경·외부 이동·새 창·다운로드까지 권한을 넓히지 않습니다.

## 보고서

실제 백엔드는 앱 데이터의 `backend-runs/<실행 ID>/`에 `report.json`, `report.html`, `report.pdf`와 실행 증거를 생성합니다. GUI는 정상 프로세스 종료뿐 아니라 해당 실행의 판정·완료 상태와 PDF 파일을 확인한 후 PDF 사본을 채팅에 첨부합니다.

검사 완료와 실제 PDF 첨부가 모두 확인되면 **버그 탐색을 완료했고 보고서를 완성했어요.**를 표시합니다. 검사 범위에 미완료 항목이 있어도 해당 실행의 PDF가 검증·첨부되면 **보고서 생성을 완료했어요.**와 **보고서 생성 완료**를 표시합니다. 실제 검사 완료 여부와 미완료 사유는 그대로 보존하며 첨부 보고서에서 확인할 수 있습니다. 이전 버전에서 보고서 첨부 후 미완료 오류로 저장된 기록도 같은 보고서 완료 표현으로 열립니다. PDF 생성·첨부에 실패하면 완료 문구를 표시하지 않으며, 이전 실행이나 기존 `testReport/report.pdf`를 새 검사 결과로 대신 사용하지 않습니다. 기존 `testReport/report.pdf`는 덮어쓰지 않습니다.

**보고서 열기**는 앱 내부 PDF 뷰어를 엽니다. 이전·다음 페이지, 페이지 번호 입력, 확대·축소·페이지 맞춤과 Esc 닫기를 지원합니다. 뷰어는 첨부된 사본을 읽기만 하며 원본 내용·스크립트·폼·외부 링크를 실행하거나 수정하지 않습니다. PDF.js와 글꼴·문자 매핑·디코더를 함께 배포하므로 외부 PDF 앱 없이 볼 수 있습니다.

실행별 보고서는 해당 실행 ID로 다시 불러옵니다. 이전 버전 기록의 보고서와 새 백엔드 결과는 구분합니다. 앱 데이터의 사본을 보관하므로 후속 검사 결과가 이전 채팅 첨부를 바꾸지 않습니다.

## 화면과 모션

흰 본문·회색 사이드바·검은 막대 로고를 유지합니다. 첫 메시지 후 중앙 입력창이 아래로 이동하고 새 설정 행이 순차적으로 나타납니다. 저장된 기록을 다시 열 때는 등장 모션을 반복하지 않으며 운영체제의 모션 감소 설정을 존중합니다.

왼쪽 **검사 기록**은 대화를, **보고서**는 보고서가 첨부되었거나 첨부 대기 중인 대화를 표시합니다. 왼쪽 아래 **QA팀**은 화면 표현용 API 설정을 열며 사이드바에 요금제·사용량을 표시하지 않습니다.

## 개발·설치·배포

Windows의 일반 Node.js 24를 사용합니다.

```powershell
npm install
npm run setup:backend
npm run desktop
```

`setup:backend`(`backend:setup`도 동일)는 백엔드 루트·qa의 잠금 파일 기준 의존성과 전용 Chromium Headless Shell을 준비하고, 현재 Node.js를 `artifacts/backend-runtime/node.exe`에 복사합니다. 준비된 의존성과 브라우저는 재사용합니다. 사이트 검사나 유료 모델 API는 호출하지 않습니다.

```powershell
npm run backend:check
npm test
npm run test:ui
npm run build
npm run package
```

`backend:check`는 설치·복사 없이 준비 상태를 확인합니다. `package`는 백엔드 준비와 GUI 빌드 후 `release/1.0.3/win-unpacked/`를 만듭니다. 배포에는 백엔드 소스·프롬프트·검사에 필요한 Playwright·Chromium Headless Shell·Node.js를 포함합니다. GUI에 사용하지 않는 전체 Chromium, QA TypeScript 컴파일러·타입 정의, 중복 UI 패키지는 제외합니다. PDF 뷰어·worker·폰트·CMaps·이미지 디코더와 각 라이브러리의 라이선스 고지는 빌드 결과에 포함하며, Electron 언어 리소스는 한국어와 영어를 유지합니다. `.env`, 실행 로그·결과, 평가 자료, 테스트 fixture, 개발 문서는 배포하지 않습니다. 개발용 MCP의 `--headed` 실행에는 전체 Chromium을 별도로 설치해야 합니다.

GUI 저장소의 배포 브랜치는 `1xx`입니다. `main`은 변경하지 않습니다. Windows 실행 폴더는 Git LFS로 관리하므로 Git LFS 설치 후 `git lfs pull --include="release/1.0.3/**"`로 실제 배포 파일을 받습니다. `WebPilot.exe`만 옮기지 말고 `win-unpacked` 폴더 전체를 함께 사용합니다. 실제 API 키·앱 개인 설정·로그인 세션·실행 기록은 소스와 배포본에서 제외합니다. 원본 WebTestPilot 저장소에는 푸시하지 않습니다.

프로젝트 안에서 실행하면 로컬 `webtestpilot-backend`를 사용합니다. 프로젝트 밖의 배포본은 `resources/webtestpilot-backend`를 사용하므로 별도 환경변수 또는 그 폴더의 `.env`로 백엔드 키를 지정해야 합니다. 키 파일은 배포본에 자동으로 복사하지 않습니다.

무료 검증은 로컬 fixture·모의 모델/자식 프로세스로 수행합니다. 실제 OpenAI·Anthropic API나 유료 사이트 검사는 실행하지 않았습니다.
